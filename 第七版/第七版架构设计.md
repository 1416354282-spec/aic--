# 第七版架构设计：R-D-FINE —— 关系感知的三模态 D-FINE 检测架构

> AIC2026 面向城市场景的视觉多模态目标检测
>
> 设计基线：第六版（RT-DETR + Tri-CSSA + 三阶段多分辨率训练，ultralytics 生态）
> 工程基线：第五版（RF-DETR 外部包包装模式 + CMTF + 条件模态 dropout）
> 核心转变：检测底座从 RT-DETR → **D-FINE**（FDR 细粒度分布回归 + OQD 查询解耦），并**首次引入目标间关系建模**（共现先验 + 空间先验 + 几何关系精炼），这是前六版从未触碰的建模层次。

## 1. 设计动机与定位

### 1.1 为什么第七版换 D-FINE 底座

| 维度 | 第六版（RT-DETR） | 第七版（D-FINE） |
|---|---|---|
| **检测范式** | 端到端 query-based，无 NMS | 端到端 query-based，无 NMS（同） |
| **骨干网络** | HGNetv2（CNN） | **HGNetv2（同一家族，同源）** |
| **编码器** | AIFI + CCFF 混合编码器 | **AIFI + CCFF 混合编码器（同构）** |
| **回归方式** | 直接回归 [cx, cy, w, h] | **FDR：逐边离散概率分布，逐层残差精炼（coarse→fine）** |
| **查询方式** | 单一 query 贯穿各层 | **OQD：内容查询 / 位置查询解耦，位置查询逐层双线性重采样** |
| **底座精度** | RT-DETR-L 53.0 AP (COCO 640px) | **D-FINE-L 54.0 AP / D-FINE-X 55.8 AP (COCO 640px)** |
| **出处** | Baidu, CVPR 2024 | **USTC, ICLR 2025 Spotlight, Apache 2.0** |
| **生态** | ultralytics 官方集成 | 独立官方仓库 `deliverChen/D-FINE`（无 ultralytics 集成） |

**选择 D-FINE 的理由**：

1. **与第六版血缘最近，迁移成本最低**：D-FINE 与 RT-DETR 同为 "HGNetv2 + AIFI/CCFF 混合编码器 + Transformer 解码器" 骨架，第六版的三尺度注入点（backbone 输出 S3/S4/S5，进 AIFI/CCFF 前）、Tri-CSSA 融合、Target-Aware Refiner、三阶段训练管线**全部原样保留**；换底座只动解码器与回归头。
2. **FDR 细粒度分布回归对小目标友好**：把框回归从"单点估计"改为"逐边离散概率分布 + 逐层残差精炼"，对定位模糊的小目标（本数据集 ball=89、uav=204、boat=135 是弱势类）天然友好，且与第六版的 denoising 训练、逐层辅助监督哲学一脉相承。
3. **OQD 查询解耦降低学习难度**：内容查询（类别语义）与位置查询（空间位置，逐层从编码器特征双线性采样）解耦，2000 张小数据下比单一 query 更容易收敛——直接回应"小数据训不动 DETR decoder"的长期风险。
4. **精度确定性收益**：L 档 54.0 vs RT-DETR-L 53.0，仅换底座即约 +1 AP；X 档（62M）作为规模消融项。
5. **Apache 2.0 许可**，官方权重离线可获取（见 §7 风险与缓解）。

**备选底座评估（为何不选）**：

| 备选 | 出处 | 不选原因 |
|---|---|---|
| DEIM | CVPR 2025 | one-to-many 匹配、小数据收敛快是真实优点；但 DINO 系底座，融合注入点需重做，工程成本高于 D-FINE。留作后续实验备选 |
| RT-DETRv4 | 2025 | 同族小步升级（L 55.4），与 v6 增量差异小，换底座的机制创新故事弱于 D-FINE 的 FDR |
| YOLOv12 | NeurIPS 2025 | attention-centric 但仍是 CNN 范式，与赛题"鼓励 Transformer 检测网络"的导向不符 |
| Le-DETR | 2026 | 高效编码器是亮点，但太新、社区验证少，权重与复现风险高 |

### 1.2 为什么新增关系感知（Relation）模块 —— 六版以来的首次目标间建模

回顾前六版："关系"建模全部发生在**模态之间**（v3 Tri-CSSA 通道评分、v5 CMTF 跨模态注意力、v6 二者对比），**目标与目标之间的关系从未建模**。第七版补齐这一层，且与赛题数据特点精准咬合：

1. **类别严重不均衡**（person 5499 >> tricycle 25）：稀有类的独立视觉证据不足，但可以借助与高频类的**共现**获得上下文提示——检测到 car 时，tricycle 的先验概率上升；检测到 boat 时，同场景其它目标的可信度应上调。
2. **城市场景有强空间先验**：uav 集中在画面上部（天空）、boat 集中在下部（水面）、sign/light 沿道路分布。这些先验从 2000 张训练集统计即可获得，是"零外部数据"下最便宜的归纳偏置注入。
3. **小数据下的关系先验是最经济的先验注入**：2000 张训不动大规模数据驱动的关系学习，但**冻结的统计先验 + 轻量几何 MLP**完全可行；且全部先验来自官方训练集，天然合规（无外部数据、离线、单模型）。
4. **附带收益**：几何关系权重天然携带 IoU/相对位置信息，对近重复预测有稀释作用，可在端到端无 NMS 的输出上进一步抑制重复框。

### 1.3 保留与升级

| 来源 | 保留内容 |
|---|---|
| **第六版** | Tri-CSSA 融合（默认）、Target-Aware Refiner 辅助监督、三尺度注入点（S3/S4/S5）、三阶段多分辨率训练、条件模态 dropout、连续质量先验、AMP NaN 兜底、16:9 letterbox 数据管线、evaluator/提交管线 |
| **第五版** | 外部包包装模式（RF-DETR 的 vendored 仓库 + 自有训练循环经验）、CMTF 融合（消融开关）、state_dict 键名映射加载经验 |
| **第三版** | Tri-CSSA 残差恒等初始化哲学、类别头随机初始化策略 |

### 1.4 一句话定位

> **第七版 = D-FINE（HGNetv2 + AIFI/CCFF + OQD 解码器 + FDR 细粒度分布回归，COCO 预训练）+ 第三版 Tri-CSSA 融合（残差恒等 + 连续质量先验）+ 第六版注入点与训练管线 + 全新 Relation-Aware Refiner（共现先验 + 空间先验 + 几何关系精炼，前六版首次目标间建模）**

## 2. 总体架构

```
输入 {rgb, ir, depth, depth_valid}   (dict, 与第六版一致)
  │
  ├─ rgb   ──→ HGNetv2 Backbone (D-FINE 官方仓库, HGNetv2-L)
  │            └──→ S3/8, S4/16, S5/32 ────────────┐
  ├─ ir    ──→ IREncoder (C3Ghost+EMA, 0.375×)      │
  │            └──→ I3, I4, I5 ─────────────────────┤
  └─ depth ──→ DepthEncoder (GhostHG+StarBlock, HHA)│
               └──→ D3, D4, D5 ─────────────────────┤
                                                     │
              ┌──────────────────────────────────────┘
              │  每尺度 Tri-CSSA 融合 (★ 默认) / CMTF (消融)
              ▼
         F3, F4, F5  ← 残差恒等初始化: F ≈ S (保护预训练分布)
              │
              ├── Target-Aware Refiner @ F3/F4 (从第三版迁移)
              │      └── soft-box mask 辅助监督 (Focal+Dice)
              ▼
   Hybrid Encoder: AIFI (S5 全局注意力) + CCFF (跨尺度融合)   [与第六版同构]
              │
              ▼
   D-FINE Decoder (300 queries, OQD 内容/位置查询解耦,
            6 层交叉注意力 + denoising 训练)
              │
              ├── FDR 头: 逐层细粒度分布回归 (粗分布 → 残差精炼)
              ▼
   boxes, class logits L, 内容查询特征 Z
              │
              ▼
   ★ Relation-Aware Refiner (本版核心新增)
     ├── 共现先验 π:  12×12 共现矩阵 (离线统计, 冻结) → 图级类别增强
     ├── 空间先验 S:  逐类中心高斯分布 (离线统计, 冻结, 熵加权)
     ├── 几何关系 W_geo: MLP([相对位置, 尺度比, IoU]) (可训练)
     └── (可选) 外观关系 W_app: query 特征点积注意力 (默认关)
              │
              ▼
   L' = L + α₁·π + α₂·S + α₃·(W_geo ⊙ L)   → 精炼分类分数, 坐标不变
              │
              ▼
   Loss = DFineLoss (varifocal cls + FDR 分布精炼 + L1 + GIoU + denoising)
        + λ_target × 目标掩码损失 (Focal + Dice, v3)
        + λ_rel × 关系精炼辅助监督 (本版新增)
```

**关键路径**：分模态编码 → Tri-CSSA 融合（残差恒等）→ 预训练 AIFI/CCFF 混合编码器 → OQD 解码器 + FDR 分布回归 → **Relation-Aware Refiner 目标间关系精炼** → 端到端输出。

**与第六版架构图的对应关系**：
- `RTDETRDecoder (IoU-aware query selection)` → `D-FINE Decoder (OQD 查询解耦 + FDR 细粒度分布回归)`
- `Loss = RTDETRDetectionLoss` → `DFineLoss`（分类/框损失同族，回归头改为分布残差精炼）
- **新增**：decoder 输出之后的 `Relation-Aware Refiner`（第六版没有这一段）
- 其余（分模态编码器、Tri-CSSA、Target-Aware Refiner、AIFI/CCFF 注入点）**全部不变**

## 3. 模块详细设计

### 3.1 数据管线（从第六版整体迁移）

| 项 | 设计 | 变化 |
|---|---|---|
| 输入 | dict `{rgb, ir, depth, depth_valid}` | = v6 |
| IR 通道 | 1 ch（mean pooling） | = v6 |
| Depth 编码 | `hha` 为主，`raw` 可选 | = v6 |
| 增强 | 水平翻转 / 仿射 / 条件模态 dropout（暗帧概率减半）/ 16:9 letterbox | = v6 |
| 分辨率 | 三阶段多分辨率，全部 32 整除 | = v6（640/1024×576/1280×736） |
| 标注格式 | **v6 自有 multimodal dataset 直出 batch，不做 COCO JSON 转换** | 说明见下 |

**关于 D-FINE 官方 COCO 格式的说明**：官方仓库自带 dataloader 要求 COCO JSON，但第七版**不采用官方 dataloader**——沿用第五版包装 RF-DETR 的模式：官方仓库只 vendored **模型定义**（backbone / 混合编码器 / 解码器 / FDR 头），数据管线、训练循环、评估、提交全部用 v6 自有实现（batch 格式与 v6 完全一致）。既规避了格式转换，又保持了六版训练逻辑的稳定性。

### 3.2 RGB Backbone（HGNetv2，vendored 自官方仓库）

- 权重：`dfine_l_coco.pt`（31.2M 参数，COCO 预训练；`dfine_x_coco.pt` 为 X 档消融项）。
- **模型构建**：按官方 `configs/dfine/dfine_hgnetv2_l_coco.yml` 构建模型 → 包装器内做 state_dict 键名映射加载（照 v5 RF-DETR 的加载适配经验）。
- **类别头处理**：预训练 80 类 → 目标 12 类。分类头（含 denoising 分类嵌入）随机初始化；backbone / 混合编码器 / 解码器主体 / FDR 回归头全部保留 COCO 预训练（v5/v6 同策略，已验证可收敛）。
- 输出：`_probe_rgb_channels` 运行时探测三尺度通道（复用 v6 逻辑；HGNetv2-L 与 RT-DETR-L 同骨干，预期 S3=512 / S4=1024 / S5=2048，实现时以探测值为准）。
- 冻结策略：Phase 1/2 冻结（BN eval 模式，v6 `enforce_frozen_eval` 迁移），Phase 3 解冻。

### 3.3 IR / Depth 编码器（从第六版整包迁移）

- `IREncoder`：Stem → C3Ghost → EMA 注意力，宽度 0.375×，三尺度输出（stride 8/16/32）。
- `DepthEncoder`：GhostHG + StarBlock，输入 3 ch（HHA 编码），同三尺度。
- 输出通道 = 0.375 × RGB 对应尺度通道。**零改动迁移**。

### 3.4 ★ Tri-CSSA 融合（默认，从第六版整包迁移）

每尺度一个 Tri-CSSA 块，输入 `(S_i, I_i, D_i)`，输出 `F_i`，五步：通道对齐 → softmax(ECA 评分 + 质量先验偏置) 模态加权 → 加权混合 → 7×7 空间注意力 → 残差恒等 `F_i = S_i + tanh(residual_scale) · spatial ⊙ Δ`（`residual_scale` 初值 0，初始 F=S 保护预训练分布）。

**保留要点（v3/v5/v6 三版验证）**：
1. 恒等初始化：residual_scale=0 → AIFI/CCFF/decoder 的预训练输入分布完全不变。
2. 连续质量先验：`q_ir`/`q_depth` 模态质量坍缩 → 赛题鲁棒性条款的一等公民设计。
3. AMP 数值稳定：融合分支强制 fp32（v5 验证 fp16 softmax 溢出 NaN）。
4. 消融开关：`model.fusion: tri_cssa | cmtf`（CMTF 从 v5 迁移）。

### 3.5 注入点（backbone 输出 → AIFI/CCFF 前，与第六版同构）

D-FINE 与 RT-DETR 共享 "HGNetv2 → AIFI + CCFF → decoder" 骨架，融合注入点**语义同构**：Tri-CSSA/CMTF 输出替换 backbone 的 S3/S4/S5，AIFI + CCFF + decoder 全部保留预训练权重——与 v6"只替换 encoder 输入"同哲学，风险最低。具体层名以 vendored 代码运行时探测为准（复用 v6 的探测思路）。

### 3.6 D-FINE 解码器适配（OQD + FDR）

- **OQD（Object Query Decoupling）**：内容查询（可学习 1D 向量，承载类别语义）与位置查询（2D 空间，逐层从编码器特征双线性采样 + 初始 top-k 选择先验）解耦。2000 张小数据下，解耦后两类查询各自职责单一，比 v6 的单一 query 更易收敛。
- **FDR（Fine-grained Distribution Refinement）**：每条框边表示为**对数空间离散概率分布**（如 32 bins）；首层产生粗分布，后续每层预测**残差分布**逐层精炼，最终框 = 跨层加权求和后的分布期望。粗→细的监督链与 denoising 训练、逐层辅助输出哲学一致。
- **denoising 训练**：官方仓库内置（与 v6 的 `get_cdn_group` 同作用），包装器保留。
- **空 GT batch**：v6 已验证的兜底逻辑沿用。

### 3.7 ★ Relation-Aware Refiner（本版核心新增）

挂载位置：decoder 输出之后、最终打分之前。输入：解码器末层输出的候选框 `B`（300×4，归一化）、类别 logits `L`（300×12）、内容查询特征 `Z`（300×d）。输出：精炼后的类别 logits `L'`，**坐标不变**（保证与 v6 提交管线兼容）。

```
L' = L + α₁·π          (图级共现先验, 冻结)
       + α₂·S          (逐 query 空间先验, 冻结)
       + α₃·(W_geo ⊙ W_app) · Ŷ        (几何/外观关系聚合, 几何 MLP 可训练)
```

#### 3.7.1 离线先验统计（`scripts/build_priors.py`，仅用官方训练集）

| 先验 | 统计方式 | 说明 |
|---|---|---|
| **共现矩阵** `P_cooc`（12×12） | `P_cooc[c_i][c_j] = P(c_i 与 c_j 同图出现)`，加性平滑防 0 | 稀有类借高频类获得上下文提示（tricycle↔car、boat↔water 场景等） |
| **空间先验** `(μ_c, Σ_c)`（12 类） | 逐类框中心 (cx, cy) 拟合 2D 高斯（归一化坐标） | uav 上半部、boat 下半部、sign/light 沿道路等城市场景先验 |
| **熵加权** | 按每类中心分布的熵缩放先验强度 | 高熵类（person/animal，分布近均匀）先验自动趋 0 → **防止伤害大分布类**；低熵类获得强先验 |

**合规性**：先验全部由官方训练集 GT 统计生成，无外部数据、无人工干预、离线运行，与赛题约束完全一致；且先验矩阵**冻结为常数**（非参数），只提供归纳偏置，不引入额外容量。

#### 3.7.2 共现先验注入（图级，向量广播）

```
Ŷ = softmax(L)                       # 300×12 软类别分布
d = mean_topk(Ŷ)                     # 图级类别分布 (top-50 置信度加权平均)
π = P_coocᵀ · d                      # 12 维: 图中已现类别带来的共现期望
L' += α₁ · log(ε + π)                # logit 空间加法偏置, 广播到全部 query
```

一张图只算一个 12 维向量，开销可忽略。与第六版 submission 中的 temporal_boost_all_person"图级类别先验增强"思路相通，但本版先验来自统计矩阵、可消融、端到端训练时保持可微。

#### 3.7.3 空间先验注入（逐 query）

```
S_i = Σ_c softmax(L_i)[c] · log N(center_i; μ_c, Σ_c)
L'_i += α₂ · S_i
```

软指派（soft-assignment）保证可微；熵加权已在统计阶段折叠进 `Σ_c`（高熵类协方差大 → log 密度平坦 → 先验自动失效）。**主要作用对象**是 uav/boat/ball 等强空间偏置的稀有类——正是赛题弱势类。

#### 3.7.4 几何 / 外观关系模块（query 间）

```
e_ij = [Δcx/w_i, Δcy/h_i, log(w_j/w_i), log(h_j/h_i), IoU_ij, 中心距]   # 不对称几何特征
W_geo = ReLU(MLP(e_ij))                                                  # 300×300, 可训练
W_app = softmax_row(⟨Z_i, Z_j⟩ / √d)                                     # 外观注意力, 默认关
L''_i = L'_i + α₃ · Σ_j (W_geo ⊙ W_app)[i][j] · Ŷ_j                      # 聚合其它 query 的类别证据
```

- **不对称特征**（相对尺度取 log 比值、中心距除以自身尺度）捕获 "支持—被支持" 方向性关系（person 支持 bicycle/seat、car 支持 tricycle）。
- **外观关系默认关闭**：小数据下 query 特征点积注意力易过拟合，作为 E4 消融开关。
- **附带重复抑制**：近重复对（IoU→1、同类）在聚合中相互稀释证据，无 NMS 输出下进一步压低重复框。

#### 3.7.5 监督与梯度设计

- 训练时在**解码器已匹配的 query-GT 对**上对精炼 logits 加辅助 varifocal 监督（复用解码器匹配结果，不新增匹配开销）。
- α₁/α₂/α₃ 小初始值 + 前 5 epoch 线性 warmup（Phase 1 先保护预训练分布，关系信号渐入）。
- 先验矩阵（共现/空间）全程冻结；仅几何 MLP 可训练（参数量 < 0.1M）。

### 3.8 检测 Loss

```
L = L_DFINE (varifocal 分类 + FDR 分布残差精炼 + L1 + GIoU + denoising 对比训练)
  + λ_target × L_target   (soft-box 目标掩码 Focal+Dice, 挂 F3/F4, 权重 0.10, v3 配置)
  + λ_rel × L_rel         (Relation-Aware Refiner 精炼 logits 的 varifocal 辅助监督, 本版新增, 权重 0.05)
```

### 3.9 推理（端到端，无 NMS）

- 解码器 eval 模式返回 top-k 后处理结果 `(B, 300, 6)` = `[cx, cy, w, h, score, cls]`（坐标归一化），与 v6 格式一致。
- Relation-Aware Refiner 只修改分数列、不改坐标 → evaluator / letterbox 逆变换 / 提交管线**零改动复用 v6**。
- 每图最多 100 框按置信度截断（赛题约束）；TTA（水平翻转 + batched NMS 合并）从 v6 迁移。
- 推理增量开销：300×300 几何 MLP + 两个 12 维向量运算，相比解码器可忽略。

### 3.10 训练策略（三阶段，从第六版迁移）

| Phase | epochs | lr | size (32 整除) | batch (5090D 32GB fp32 实测) | 冻结 |
|---|---|---|---|---|---|
| 1 | 20 | 1e-3 | 640×640 | 12×4 (等效 48) | backbone + neck + decoder（只训新分支 + Refiner） |
| 2 | 85 | 5e-4 | 1024×576 | 8×4 (等效 32) | backbone（解冻 neck+decoder，0.1×lr） |
| 3 | 45 | 1e-4 | 1280×736 | 4×8 (等效 32) | 全解冻 |

> batch 为 5090D 32GB **全 fp32 前向+反向**的实测安全值（优先数值精度, 溢出降 batch 而非开 AMP; bs16@640 / bs12@1024×576 / bs6@1280×736 均超或贴上限）。等效 batch 经梯度累积保持与原始计划一致 (48/32/32)。

- AdamW + warmup 3ep + cosine + EMA 0.9999 + AMP + grad_clip 10 + 梯度累积（v6 全部保留）。
- **训练循环用 v6 自有 trainer**（不采用官方仓库 torchrun 脚本），phase 冻结配置修复（`set_phase` 读 phase 配置）沿用 v6。
- AMP NaN batch 跳过（v6 兜底保留）；融合与 Refiner 分支 fp32 包裹。

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| **D-FINE 无 ultralytics 集成** | 采用第五版 RF-DETR 包装模式：vendored 官方仓库只取模型定义，数据/训练/评估/提交全部用 v6 自有实现——v5 已完整踩过一遍外部包包装的坑 |
| **官方权重加载键名不匹配** | 包装器内 state_dict 键名映射（照 v5 经验）+ tests 冒烟校验逐层形状 |
| **权重获取被墙** | 官方权重在 HuggingFace（ArgoSA/D-FINE-seg, `dfine_l_coco.pt` 31.2M），经 `hf-mirror.com` 镜像下载（与 v6 用 ghfast.top 下 rtdetr 同思路），下载后随 sync 脚本传到训练机 |
| **Objects365 预训练版本合规灰色** | 官方另有 Objects365 预训练版（GOLD 蒸馏, 57.1 AP），但赛题"严禁私自扩充外部数据"条款下存在解读风险——**默认只用 COCO 预训练**，Objects365 版本不碰 |
| **2000 张数据训不动 DETR decoder** | ① 全套 COCO 预训练 + Phase 1 冻结保护；② OQD 查询解耦本身降低收敛难度；③ denoising 训练 + Target Mask 锚点；④ 先跑 E0 验证底座收敛性，异常则回退 v6 保底 |
| **关系模块在小数据上过拟合** | ① 共现/空间先验冻结（非参数），只训 <0.1M 的几何 MLP；② 外观注意力默认关；③ α 系数小值 + warmup；④ E2/E3/E4 逐级消融，每级无独立收益即不保留 |
| **类别头随机初始化（nc 80→12）** | 仅解码器分类头随机化，backbone/编码器/FDR 回归头全保留；v5/v6 同策略验证过可收敛 |
| **AMP 数值不稳定** | Tri-CSSA/CMTF/Refiner 强制 fp32（v5 验证）+ trainer NaN batch 跳过 |
| **冻结 BN 统计漂移** | `_set_frozen_eval` 冻结层切 eval 模式（v6 已修复，沿用） |
| **高分辨率过拟合** | 高分辨率仅限 Phase 3 精调；EMA + 强增强 + 类别平衡采样延续 v6 |
| **推理坐标格式变化** | Refiner 只改分数不改坐标，输出仍为归一化 [cx,cy,w,h,score,cls]（与 v6 一致），evaluator 零改动 |

---

> **结论**：第七版以 D-FINE 为检测核心（HGNetv2 + AIFI/CCFF + OQD 查询解耦 + FDR 细粒度分布回归，COCO 预训练），完整保留第六版的三模态融合（Tri-CSSA）、注入点、辅助监督与三阶段训练管线，并**首次引入目标间关系建模**——Relation-Aware Refiner 以官方训练集统计的共现矩阵与空间先验（冻结、熵加权）为基，配合轻量几何关系 MLP 精炼解码器分类分数。底座换装带来确定性精度收益（54.0 vs 53.0 AP）与小目标友好的回归机制，关系模块直面类别不均衡与城市场景先验，全部先验仅来自官方数据，天然合规。代码迁移率 ≥70%，创新点集中在"D-FINE × 三模态融合 × 目标关系感知"的三元组合，且每一步均有独立消融实验背书。
