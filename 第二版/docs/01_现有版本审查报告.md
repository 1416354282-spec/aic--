# 现有版本审查报告

## 总结

第一版具备 YOLOv8 五通道 Early Fusion 的基础骨架，但“配置中写了什么”和“实际执行了什么”严重脱节。继续堆叠注意力模块之前，必须先修复验证、解码、数据划分和增强标签等正确性问题。

## P0：会直接影响分数可信度的问题

1. `src/infer.py` 的 anchor 使用 feature-grid 单位，而回归距离乘了 stride；验证和提交脚本使用像素单位，两套结果不一致。
2. 训练、验证、推理、提交均调用类别无关 NMS，不同类别的重叠目标会互相抑制。
3. 每个 anchor 只保留最大类别，尾类容易被头类分数压制。
4. 按单帧随机 80/20 划分。文件名明显包含序列信息，精确重复帧也可能跨 train/val，验证存在场景泄漏。
5. 训练内验证临时把 BN `eps` 改为 0.01，而正式验证和推理不改，best checkpoint 的选择口径不一致。
6. 解码和 mAP 代码在四处复制，已经发生实现漂移。

## P1：数据和增强问题

- 训练集 2000 张、14417 个框，类别从 person 5499 到 tricycle 25，相差约 220 倍。
- 409 个框严格越界，861 个框接触或越界。第一版既不清洗原始框，仿射后也只过滤、不裁剪重算。
- 约 75.9% 的框面积低于整图 1%，属于显著小目标任务；但 1920×1080 / 640×360 都直接拉伸成 640×640。
- Mosaic、MixUp、Copy-Paste 配置没有进入训练链路。现有 Mosaic 还有 `target_h / w`、负切片、标签按模态重复追加等 bug。
- `BalancedBatchSampler` 未接入，而且只重排、不真正增加尾类曝光。
- JPG depth 全部置零是未经消融的强假设；没有 validity mask，模型无法区分无效像素和整模态缺失。

## P1：训练与复现问题

- `cls_weights` 和自定义 weighted loss 未接入。
- argparse 默认值总是覆盖 YAML；大量配置字段无效。
- cosine 最终学习率降为 0，忽略 `cos_lr_final`。
- resume 只恢复模型和 epoch，不恢复 optimizer、scheduler、scaler、EMA、best metric 与随机状态。
- 最终 `last.pt` 覆盖掉较完整的 checkpoint。
- 固定每 25 epoch 验证，忽略配置。
- 同名实验目录会覆盖；没有 resolved config、版本与 split hash。

## 第二版原则

先建立共享且可测试的 decode/NMS/metric、无泄漏 split、letterbox 和合法标签，再逐项做尺寸、模型、模态、增强、长尾和融合消融。任何配置项要么真正生效，要么启动即报错。
